SERVER - Migrate of data from old server to new server
------------------------------------------------------
VERSION_INITIAL: 1.16
VERSION_UPDATED: 1.16
REQUIRED: <OLD_SERVER_USERNAME>, <OLD_SERVEFR_PASSWORD>, <OLD_SERVER_IP>, <MYSQL_ROOT_PASSWORD>
OPTIONAL: n/a

REF: https://docs.observium.org/server-migration/

-Log onto the **NEW** server to do this work:

SH> cd /opt/observim
SH> grep db config.php

-Save all of this information, it will be needed later

-Log onto the **OLD** server to do this work:

SH> cd /opt/observim
SH> grep db config.php
SH> mysqldump -u observium -p --databases observium --no-tablespaces --add-drop-table --extended-insert > observium-dump.sql

-There will be a prompt for a password, enter from the previous grep
-check for the dump with the following command:

SH> ls -l *.sql

-Now we will tar the RRD files with the following command:
SH> tar zcvf observium-rrd.tar.gz rrd

-This work will need to be done on the **NEW** Server:

SH> cp config.php config.php.old
SH> scp <OLD_SERVER_USERNAME>@<OLD_SERVER_IP>:/opt/observium/observium-rrd.tar.gz /opt/observium/
-Enter <OLD_SERVEFR_PASSWORD>, when prompted
SH> scp <OLD_SERVER_USERNAME>@<OLD_SERVER_IP>:/opt/observium/observium-dump.sql /opt/observium/
-Enter <OLD_SERVEFR_PASSWORD>, when promptedSH> sudo bash
SH> scp <OLD_SERVER_USERNAME>@<OLD_SERVER_IP>:/opt/observium/config.php /opt/observium/
-Enter <OLD_SERVEFR_PASSWORD>, when prompted

SH> sudo nano config.php

-Look in the file for db_pass, and replace the password from the old file with the new one.  Both should be saved.
-Save and exit the file

SH> echo "SET FOREIGN_KEY_CHECKS = 0;" > ./drop_all_tables.sql
( mysqldump --add-drop-table --no-data -u root -p observium | grep 'DROP TABLE' ) >> ./drop_all_tables.sql
-Enter  <MYSQL_ROOT_PASSWORD> when prompted

SH> echo "SET FOREIGN_KEY_CHECKS = 1;" >> ./drop_all_tables.sql
SH> mysql -u root -p observium < ./drop_all_tables.sql
-Enter  <MYSQL_ROOT_PASSWORD> when prompted

SH> mysql -u observium -p observium < observium-dump.sql
-Enter the password for the mysql user 'observium' when prompted

SH> mv rrd rrd.old
SH> tar zxvf observium-rrd.tar.gz

-Test by logging into app, it should have all of the old systems and their RRD data.

CLIENT - Install and configure SNMP v3 for Redhat / CentOS
----------------------------------------------------------

SH> sudo yum install net-snmp
SH> sudo service snmpd stop

-PASSWORD1 and PASSWORD2 will be replaced with the actual passwords that are stored in KeePass

SH> sudo net-snmp-create-v3-user -ro -A **PASSWORD1** -a SHA -X **PASSWORD1** -x AES monitor

-Edit the following file:

SH> sudo nano /etc/snmp/snmpd.conf

-and make the following changes, but replace with actual data:
sysLocation    xx.xxxxxx -xx.xxxxxx ** IN KEEPASS **
sysContact     xxx xxxxxxxx ** IN KEEPASS **

-Optional, add these lines to get more detailed information:

# This line allows Observium to detect the host OS if the distro script is installed
# extend .1.3.6.1.4.1.2021.7890.1 distro /usr/local/bin/distro
# This lines allows Observium to detect hardware, vendor and serial
extend .1.3.6.1.4.1.2021.7890.2 hardware /bin/cat /sys/devices/virtual/dmi/id/product_name
extend .1.3.6.1.4.1.2021.7890.3 vendor   /bin/cat /sys/devices/virtual/dmi/id/sys_vendor
extend .1.3.6.1.4.1.2021.7890.4 serial   /bin/cat /sys/devices/virtual/dmi/id/product_serial
# This line allows Observium to collect an accurate uptime
extend uptime /bin/cat /proc/uptime
# This line enables Observium's ifAlias description injection
#pass_persist .1.3.6.1.2.1.31.1.1.1.18 /usr/local/bin/ifAlias_persist

SH> sudo service snmpd start


Optional: testing to see if SNMP is working

SH> yum install net-snmp-utils
SH> snmpwalk -v3 -u monitor -l authNoPriv -a SHA -x AES -A **PASSWORD1** -X **PASSWORD2** localhost

CLIENT - Configuration of OPNsense router
-----------------------------------------
VERSION_INITIAL: 1.15
VERSION_UPDATED: 1.17
REQUIRED: <SNMP_COMMUNITY>, <LOCATION>, <CONTACT>
OPTIONAL: n/a

-This is a lot harder than pfsense, because it looks like that SNMP is not built into the GUI, and all work needs to be done on the CLI
REF: https://forum.opnsense.org/index.php?topic=33481.0

-Use Putty to get to the server, then log onto the console
SH> vi /etc/rc.conf.d/bsnmpd
-Add the following line then save and exit:

bsnmpd_enable="YES"

-If this is the first time, do the following steps:
SH> vi /etc/snmpd.config

-Change the following lines:
location := <LOCATION>
contact := <CONTACT>
read := <SNMP_COMMUNITY>

-Find the following lines and remove the comments:
begemotSnmpdModulePath."hostres" = "/usr/lib/snmp_hostres.so"
begemotSnmpdModulePath."pf" = "/usr/lib/snmp_pf.so"

-Save and exit the file
-Copy the file snmpd.config to snmp.config.good becasue every time that OPNsense does an upgrade, it wipes out this file.

SH> cp /etc/snmp.config /etc/snmp.config.good

-If the previous section has been done before, do the following commands:

SH> cp /etc/snmp.config.good /etc/snmp.config

-Start the service:
SH> /etc/rc.d/bsnmpd start

CLIENT - Configuration of Windows 10 / 2012
-------------------------------------------
VERSION_INITIAL: 1.09
VERSION_UPDATED: 1.14


-For Windows 10, open Powershell as an administrator and install the following components:
PS> Add-WindowsCapability -Online -Name "SNMP.Client~~~~0.0.1.0"
PS> Add-WindowsCapability -Online -Name "WMI-SNMP-Provider.Client~~~~0.0.1.0"

-For Windows 10, Verify the installation of the components:
PS> Get-WindowsCapability -Online -Name "SNMP.Client~~~~0.0.1.0"
PS> Get-WindowsCapability -Online -Name "WMI-SNMP-Provider.Client~~~~0.0.1.0"

-For Windows 2012, open Powershell as an administrator and install the following components:
PS> Install-WindowsFeature SNMP-Service,SNMP-WMI-Provider -IncludeManagementTools

-For Windows 2012, verify the installation of the components:
PS> Get-WindowsFeature SNMP*

-For Windows 2008R2, use DISM to install SNMP:
ADMIN-CMD> dism /online /enable-feature /featurename:SNMP 
ADMIN-CMD> dism /online /enable-feature /featurename:WMISnmpProvider

-For Windows 10, Log onto system
-Open Computer Manager with administrative privileges
-Create a user with the following criteria:
--Name:						monitor
--Password:					**IN KEEPASS**
--User must change password at next logon:	unchecked
--User cannot change password			checked
--Password never expires:			checked
--Member of:					Users, Distributed COM Users, Performance Monitor Users

-For Windows 10, Run dcomcnfg, enter administrative privlidges
-Browse to Computer Services, Computer, My computer then right click, [properties]
-Go to 'Launch and Activation Limits', click 'Edit Limits'
--Add the user Monitor with the following criteria:
---Local Launch:		allow
---Remote Launch:		allow
---Remote activation:		allow
-OK, OK to close

-run services.msc
-Stop the SNMP service
-Make the following adjustements:
--Agent: Contact:			xxx xxxxx ** IN KEEPASS **
--Agent: Location:			xx.xxxxxx -xx.xxxxxx  ** IN KEEPASS **
--Agent: Service: Physical:		Checked
--Agent: Service: End-to-End:		Checked
--Security: Send Authentication Trap:	Unchecked
--Security: Community:			monitor / READ ONLY
--Security: Accept SNMP Packet:		Accept SNMP packets from these Hosts
--Security: Accept SNMP Packet (IP):	** IN KEEPASS **
-Save and Start the service
